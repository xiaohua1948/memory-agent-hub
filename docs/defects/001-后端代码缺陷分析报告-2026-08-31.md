## 一、严重级缺陷

### 1.1 回收站定时任务误删其他用户文件（数据丢失级）

**位置**：`RecycleServiceImpl.cronDropPicture`（67-81 行）

```java
67:  QueryWrapper<UserFileEntity> queryWrapper = new QueryWrapper<>();
68:  for (FileEntity fileEntity : list) {
70:      queryWrapper.eq("file_id",fileId);   // ⚠️ 同一个 wrapper 循环内叠加条件
71:      List<UserFileEntity> userFileEntities = userFileMapper.selectList(queryWrapper);
72:      if(userFileEntities.isEmpty()){ ... 物理删除 file 记录 + MinIO 对象 }
```

**问题**：MyBatis-Plus 的 `eq` 是 AND 叠加。第二次循环起条件变为 `file_id='a' AND file_id='b'`，永远为空，导致**即使其他用户仍持有该文件（user_file 有正常记录），也会被物理删除**。配合秒传功能（文件可多用户共享 MD5），造成其他用户数据损坏。

**触发频率**：每 50 分钟由 `CronSyncTask.CronDropPictureSync` 触发一次。

**修复建议**：`new QueryWrapper<>()` 移入循环体内。

---

### 1.2 登录接口把密码哈希返回给前端

**位置**：`UserLoginVO.java:18`、`AuthServiceImpl.accountLogin:128`、`codeLogin:173`

**问题**：`UserLoginVO` 直接嵌套整个 `User` 实体，`User` 含 `password`、`role` 字段且无 `@JsonIgnore`，两处登录都执行 `userLoginVO.setUser(user)`，**BCrypt 密码哈希直接下发到浏览器**。

**修复建议**：新建不含 password 的 UserVO 返回；或 `User.password` 加 `@JsonIgnore`。

---

### 1.3 验证码校验 NPE（验证码过期即 500）

**位置**：`AuthServiceImpl.codeLogin:156`、`updateEmail:228`

```java
String redisCode = redisUtil.get("email:code:" + email).toString();  // 过期时 null → NPE
```

**修复建议**：先判空再比较，过期时返回业务提示"验证码已过期"。

---

### 1.4 updateEmail 清理验证码用错方法（必然报 Redis 错误）

**位置**：`AuthServiceImpl.java:257`

```java
redisUtil.sClear(redisKey);   // sClear 是 Set 类型操作（RedisUtil:299，opsForSet）
```

**问题**：验证码实际用 `set()` 存的 String 类型，对 String key 执行 Set 删除抛 Redis WRONGTYPE 异常 → **邮箱改成功了但接口返回 500**。

**修复建议**：改为 `redisUtil.delete(redisKey)`。

### 1.5 下载接口空指针顺序错误

**位置**：`FileController.downloadFileByToken`（208-215 行）

```java
210:  DownLoadInfoDTO dto = (DownLoadInfoDTO) redisUtil.get("tempDownload:" + downloadToken);
212:  if (downloadToken == null) { throw ... }      // 判空在 get 之后，顺序反了
215:  List<String> fileIds = dto.getFileIds();      // token 过期时 dto 为 null → NPE
```

**修复建议**：先校验 downloadToken，再判 dto == null 抛"令牌已过期"。

### 1.6 越权访问（多处缺少归属校验）

| 位置 | 问题 |
|------|------|
